# Maturity Anti-Patterns (CR-VAS-006)

## Purpose

Per CR-VAS-006 §21, the following anti-patterns SHALL explicitly be
rejected. None of these constitute evidence of AVS maturity.

## The Eight Anti-Patterns

### 1. Maturity = Autonomy

**Incorrect:** "Higher autonomy means higher maturity."

**Rejected because:** higher autonomy is not inherently more mature.
A mature AVS may deliberately retain human approval, escalation, and
conservative authority limits.

### 2. Maturity = AI Sophistication

**Incorrect:** "More advanced models mean higher AVS maturity."

**Rejected because:** AI model sophistication is an implementation
technology characteristic, not an organizational capability
assessment.

### 3. Maturity = Agent Count

**Incorrect:** "More agents means greater maturity."

**Rejected because:** agent count is a portfolio size measure, not
a capability measure. An organization with many poorly governed
agents is LESS mature, not more.

### 4. Maturity = Automation Percentage

**Incorrect:** "More automated stages means higher maturity."

**Rejected because:** automation percentage conflates automation
with agenticity and conflates volume with quality of governance.

### 5. Maturity = Intervention Reduction

**Incorrect:** "Fewer human interventions automatically means
higher maturity."

**Rejected because:** intervention is a deliberate control
mechanism, not a defect. Removing interventions solely to increase
an automation score degrades risk and governance capability.

### 6. Maturity = Cost Reduction

**Incorrect:** "Lower operating cost automatically means higher
maturity."

**Rejected because:** cost reduction is a potential outcome, not
a definition of organizational capability. Cost reduction without
value or risk management is not maturity.

### 7. Maturity = Production Deployment

**Incorrect:** "A production deployment automatically constitutes
mature AVS capability."

**Rejected because:** production deployment without systematic
measurement, governance, risk management, and improvement is L3
implemented at best, not L4 managed or L5 scaled-adaptive.

### 8. Maturity = Semantic Complexity

**Incorrect:** "More relationships, agents, policies or semantic
constructs imply greater maturity."

**Rejected because:** semantic complexity is a vocabulary property,
not a capability property. Maturity is about repeatable,
evidence-based capability, not model cardinality.

## Detection Heuristics

| Anti-Pattern | Detection signal |
|---|---|
| Maturity = Autonomy | Dashboard reports autonomy percentage as primary maturity indicator |
| Maturity = AI Sophistication | Maturity scores correlate with model version, not governance practice |
| Maturity = Agent Count | Headcount of agents is reported as maturity metric |
| Maturity = Automation Percentage | Automation ratio is reported as maturity metric |
| Maturity = Intervention Reduction | Lower intervention count is celebrated without context |
| Maturity = Cost Reduction | Cost per outcome is sole maturity measure |
| Maturity = Production Deployment | Maturity tier increases automatically on deployment date |
| Maturity = Semantic Complexity | Maturity score rises as ontology cardinality grows |
